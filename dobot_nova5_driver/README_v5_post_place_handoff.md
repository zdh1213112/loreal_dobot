# V5 放料后退出与下一次抓取交接（2026-10-20）

## 卡住的原因

日志里 D405 已在约 0.81 秒完成识别。101 启用抓取防护后，102 停在 `XYZ=(485,302,165)mm`：仍满足 `Y>300, X<535, Z>75`，因此 101 不允许接近。同时 102 的 VLA 已暂停，其恢复函数原来在抓取防护开启时一律返回。双方形成等待，空盘探测日志只是等待期间的附带信息。

## 新的交接行为

1. 已确认 102 完成放料并退出触发转盘后，先核实 101 的实测关节处于初始位、机器人为静止状态。101 保持初始位；102 继续原来的 VLA 退出、取下一件物料的动作流。
2. 102 用新鲜实测位置和最近已发送的目标段验证退出；保留原有提前量。例如 Y 边界 300mm、提前量 10mm 时，危险 X/Z 侧需退到 290mm 或更外侧。X 或 Z 已安全离开时，按三维区域判断。
3. 退出确认后，101 切换为抓取防护，等待 102 清理旧指令并确认新的防护状态，再连续确认安全位置至少 100ms，随后执行抓取。
4. 101 抓取期间，102 的路径只要通过三维安全检查，仍可继续取料。检查同时覆盖实测位置、上一发送目标和下一目标；跨入抓取区域的动作才等待。
5. 放料区域租约继续生效：退出交接不等于允许向已有物料的转盘放入另一件。反馈过期、失联、取消或初始位失去验证时，退出交接状态结束并恢复抓取防护。

这里使用 VLA 当前动作、实测反馈和已下发的目标段判断路径；没有把模型尚未下发的未来动作当作退出证明。

## 协议与日志

`/dual_arm_102_guard_xyz` 保留五个数值，最后一项：`3` 表示 101 在初始位等待 102 退出；`2` 表示执行抓取防护。切换阶段会更新序号，101 要求当前阶段的确认，旧确认不能放行。

101 等待日志为 `101 startup handoff wait`，包含交接阶段、102 XYZ、区域是否安全、租约和确认序号。102 状态新增 `handoff_exit_wait`。

101 V5 驱动与 102 的 `examples/dobot_nova5_dh_v5/{real_env,turntable_lease}.py` 需要配套重启。旧版 102 不识别交接阶段，会保持关闭等待。V4/V5 的 D405 新鲜度及悬停重试优化继续使用各自实现；这次新增的双臂交接协议属于 V5。

离线覆盖：302mm 退出不中断 VLA、当前段或已发目标未安全退出时不确认、新阶段确认、退出后并行取料、危险路径禁止恢复、旧反馈、租约、等待取消和初始位验证。未驱动真机运行，实际节拍与连续运行效果需通过现场运行确认。
