# V4 / V5 D405 抓取重试优化（更新于 2026-10-22）

针对 `continuous-18/19/20` 日志中的两次接近后退回、第三次才夹取：

- 重试曾直接接收 `age=2.618s` 的旧停盘跟踪缓存，同时重新启动 D405，导致机器人离开初始位后视觉才按固定 ROI 重识别。
- 悬停校验缺少新鲜帧时原来立即失败，没有给短暂跟踪中断留出恢复时间。

## 修改后的行为

1. 启动预跟踪、停盘重识别和显式视觉请求都设置新的采集时间边界。视觉处理循环实际开始采集后，通过现有 `/d405_vision_result` 话题发送 `acquisition_started:<request_epoch>:<capture_epoch>`。这类消息不计入检测成功、失败或空盘确认。
2. 驱动等待采集确认，并拒绝前一轮及采集边界之前的图像结果；相机端也禁止旧采集帧进入新的稳定帧组合。推理过程中到达的新请求不会被旧循环清除触发标志的操作吞掉。
3. 停盘预跟踪目标同时检查接收时间、图像采集时间和本轮计数，继续要求稳定样本、CLEAR 状态及尺寸合法。
4. 确认安全悬停高度后，如缺少合格跟踪帧，先等待 0.60 秒。到期时，如果本次等待内采集时间确实前进，且最近 0.20 秒仍收到延迟帧，可额外等待一次，默认总上限 1.60 秒，任何配置的总上限为 2 秒。延长等待还要求图像年龄不超过新鲜度限制加最多 1 秒；停流、重复旧图、跨轮次图像不能触发额外等待。已有合格帧立即继续；等待期间不由驱动触发 YOLO 或发送运动指令，安全停止仍可打断。超时仍回初始位重试。
5. 固定 ROI 选择范围保持原样。通过先在初始位完成本轮重识别，避免旧缓存让机器人先行离开，再异步重置 SAM2。持续遮挡、真实障碍或目标身份变化仍可能触发重试。
6. 视觉取帧在首次阻塞读取后，有限次非阻塞读取已就绪的同步帧组，优先使用最新一组；不拼接不同帧组的 RGB、红外或深度。首次 YOLO 与后续 FFS/SAM2 仍使用同一组图像。保留真实采集时间，异常时间戳禁止发布位姿，不能把旧图像的返回时间当成新采集时间。

## 参数和使用

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `pregrasp_fresh_wait_timeout_s` | `0.60` 秒 | 悬停缺帧的基础等待，范围 0–2 秒；0 表示不等待，也不启用额外等待 |
| `pregrasp_tracking_recovery_grace_s` | `1.0` 秒 | 仅延迟跟踪仍更新时额外等待一次，范围 0–2 秒；基础加额外等待最多 2 秒；0 恢复原基础等待行为 |
| `pregrasp_pose_max_age_s` | `0.65` 秒 | 新鲜度限制，停盘跟踪与悬停检查同时校验接收、采集时间 |

两个版本的 D435 launch 均暴露等待参数，例如在原有启动命令末尾追加：

```bash
pregrasp_fresh_wait_timeout_s:=0.6 pregrasp_tracking_recovery_grace_s:=1.0
```

驱动、对应版本 D405 视觉脚本应配套重启。已运行的进程不会自动加载这些修改。启动入口继续使用各自 V4 / V5 的源码视觉脚本；驱动及 launch 的安装副本同步更新。

日志新增 `capture_age`，悬停等待时会出现 `D405 tracking gap at safe hover`；符合额外等待条件时出现 `extending safe-hover wait once`，恢复后出现 `D405 fresh tracking recovered at safe hover`。失败信息同时列出最近接收年龄和采集年龄，便于区分旧图像与无回包。下降时的接收和采集年龄仍须符合原来的 0.65 秒限制，延长等待不放宽这一限制。
