# V4 / V5 D435 侧面条码确认

本轮优化保留 launch 中的 `turntable_d435_confidence:=0.40`、完整推理视野、局部/分块回退，以及 YOLO 和 OpenCV 两条独立检测路径。

## 确认与疑似候选

- 每张图同时检查 YOLO 和 OpenCV。YOLO 的 detail/full/tile 结果属于同一路；OpenCV、未通过结构校验的 OpenCV 候选和运动条纹各自计数。不同来源不能互相凑够确认次数，同一帧也不能重复计数。
- YOLO 仍默认要求 2 次同位置有效命中，最大间隔 0.70 秒、IoU 至少 0.15。原有置信度、ROI、面积、细节和平行条纹条件保持。
- OpenCV 独立确认仍默认要求 3 次有效命中，最大间隔 0.25 秒、IoU 至少 0.20；新增细节/平行条纹检查，倾斜候选先使用检测四边形做透视校正后再次检查，不强制要求 YOLO 同时检测到。
- OpenCV 框如果结构不清晰，保留为 `scanner_unverified` 疑似候选，不能发布 `success` 或连续存在确认。短暂漏一帧不会立即丢弃候选，它按时间自动过期。
- 同位置匹配失败、扫描重新启用或 ROI 改变会隔离旧证据。旧扫描推理回包不能借连续检测开关进入新扫描。

### 黑色文字/塑封反光误检过滤

2026-10-21 的真实记录 `d435_confirm_1792553545864202496_g1_f298` 将黑色印刷文字区域
判为条码，YOLO 分数约 0.493，框为 `(598,261,246,196)`，现场用户确认并非条码。
原有边缘段数、22% 线覆盖和主方向均值比允许这类短边缘纹理通过，两帧重复命中
也不能纠正同一模型的稳定误判。

fast D435 的条纹检查新增平滑后梯度方向一致性校验（结构张量特征值对比至少 0.30），
用于排除缺乏统一条纹方向的文字/反光纹理。先抑制像素噪声，保留模糊真条码的
主要方向；原有线覆盖、置信度 0.40、两帧确认和模型保持原值。新增校验本身不调用模型，
未通过时继续沿用原有全幅/分块回退与转盘搜索流程。
该校验同时用于 YOLO 和 OpenCV 结构确认；未通过的 OpenCV 候选仍可请求补拍，
不能发布成功确认。V4/V5 使用同一 fast 模块。

回归包含该次误检原始/锐化局部图、七张已目视检查的历史真条码，以及暗光、
轻度模糊、横竖方向和小角度倾斜样例。它只证明这些已验证场景的表现，不能替代
现场误检率和召回率评估；仍需继续保留新出现的误检/漏检记录。

## 转盘补拍

候选通过独立的 `/turntable_barcode_candidate` 话题报告。该话题只请求更清晰的观察，不能授权抓取；侧码确认仍由原来的 `/turntable_barcode_result` 发布。

正常候选先按原有帧数快速确认。候选持续未确认时，V4/V5 使用现有可靠的停盘脉冲暂停转盘，并额外观察少量静止帧。收到侧码或顶部确认就保持停止；仍未确认则在检查 102 净空后继续剩余旋转搜索。

候选停盘/观察/重启耗时不占原旋转搜索预算，也不提前触发 D405 抓取。最终停止后，继续重新采集 D405 的抓取目标。取消、换料或关闭扫描会中止补拍，不会自动重启转盘。

| launch 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `turntable_d435_confidence` | `0.40` | YOLO 候选置信度 |
| `turntable_d435_yolo_stable_hits` | `2` | YOLO 独立确认次数 |
| `turntable_d435_scanner_assist_hits` | `3` | OpenCV 独立确认次数 |
| `turntable_candidate_grace_s` | `0.12` | 持续疑似候选进入补拍前，留给正常确认的时间 |
| `turntable_candidate_recheck_s` | `0.35` | 停盘脉冲完成后的额外观察上限；范围 0–2 秒 |
| `turntable_candidate_max_rechecks` | `2` | 一次物料扫描最多补拍次数；设为 0 可关闭候选停盘 |

额外观察时间不包括现有停止/启动脉冲。仅在疑似候选持续出现时产生补拍等待，已有成功确认立即进入原有停盘流程。

例如保留检测优化、关闭额外停盘：

```bash
ros2 launch dobot_nova5_driver cosmetic_box_single_arm_cycle_v5_d435.launch.py \
  turntable_candidate_max_rechecks:=0
```

V4 使用对应的 `cosmetic_box_single_arm_cycle_v4_d435.launch.py`。

## V5 确认画面回看与误检记录

V5 默认保留历史确认小图（`turntable_d435_confirmation_review:=true`），
默认关闭自动保存（`turntable_d435_confirmation_save:=false`），两个开关相互独立。
V3/V4 保持原设置。以下是确认后的显示和可选记录功能，检测阈值、两帧确认条件及机械臂/转盘控制条件保持原值。

- 确认帧立即发布预览，不受普通 0.1 秒预览间隔影响。
- D435 预览右下角保留 5 秒的紫色历史确认小图，标记 `LAST CONFIRM - HISTORY`、
  确认后经过时间、检测来源和 YOLO 分数。实时画面继续更新；历史框不会叠加到新的实时物料上。
- 开启自动保存后，每次实际发布成功确认时，保存同一帧的 `raw.png`、`annotated.jpg`、`crop.png`
  和 `record.json`，目录为 `/home/zdh/ffs_ws/d435_barcode_confirmations/d435_confirm_*`。
  JSON 记录候选框、分数、帧数、扫描代次、硬件帧号/时间戳、模型、ROI 和确认次数。
  OpenCV/几何路线没有模型分数，界面显示 `n/a`。
- 工作流确认与连续检测在同一帧同时发布时，只记录一份。候选提示、弱条纹和
  尚未满足确认次数的检测不生成成功记录。
- 最近 100 份记录由独立、有界的文件写入队列保存，编码和磁盘 IO 不放在相机推理线程。
  文件错误只告警，不改变确认结果或运动。队列拥塞会明确报告该份记录未保存。
  自动清理只处理本功能创建的记录；含用户额外文件的目录、无关目录和符号链接不会删除。
- 自动保存关闭时，不创建文件写入线程或记录目录，不写入或清理历史记录；小图仅在内存中保留。
  预览界面的空格键仍可按需手动保存原图。

保留小窗口、关闭自动保存，在原 V5 launch 命令后使用（重启 launch 后生效）：

```text
turntable_d435_confirmation_review:=true turntable_d435_confirmation_save:=false
```

之前启动命令中的 `turntable_d435_confirmation_review:=false` 需要改为 `true` 或移除，
否则会覆盖新的默认值并继续隐藏小窗口。需要排查误检并自动留图时，单独设置
`turntable_d435_confirmation_save:=true`；需要关闭历史小窗口时，设置
`turntable_d435_confirmation_review:=false`。

早先没有保存的误检画面无法由旧日志还原。历史回看不代表额外一次条码校验，
也不表示已成功解码条码内容；后续应使用真实误检原图验证模型和结构过滤的调整。

## D405 顶面文字误检过滤（V4 / V5）

2026-10-22 的顶面记录 `1792640545407948372` 中，YOLO 将盒身密集文字
误认为条码，两帧分数为 0.50、0.81。文字确实位于盒子顶面，因此通过了
原有的两帧顶面深度校验；深度校验不能独自证明内容是条形码。

V4、V5 共用的 `top_surface_barcode_detector_v3.py` 现在对 YOLO 候选先检查
多个平行长边，以及沿长边采样的明暗截面是否一致。检查方向由实际边缘确定，
不要求条码水平或竖直；为模型补出的重复边框像素不参与结构证据。
结构不合格的候选不会进入顶面深度/成功确认，日志会显示
`YOLO candidates without consistent parallel bars`，调试 JSON 在候选中记录
`bar_structure`。后续继续原有找码流程。

原有模型、0.40 置信度、两帧及实时顶面深度验证继续使用；ZBar/OpenCV
实际解码路径保留。重启对应 V4/V5 launch 后加载共用模块的新版本。

离线回归包含 13 张真实文字/包装候选、20 张真实小尺寸/模糊/旋转条码候选，
以及淡色、旋转条纹和原有顶面深度/抓取流程测试。另用原模型在 CPU 上回放
本次两张误检帧和 20 张已核对的真条码完整图像与 SAM 掩膜：两张误检均被排除，
20 张真条码均保留。该样本验证不代表所有包装的误检率或召回率，尚未实机运行。

## 验证范围

离线测试覆盖两路独立确认、混合来源不累计、同帧去重、暗光/轻度模糊/旋转条纹、无条纹候选保留、过期和跨轮数据拒收，以及 V4/V5 补拍成功、超时恢复、取消和完整旋转预算。

对现有样本目录均匀抽取 32 张原图进行 CPU 回放，7 张出现 YOLO 候选，优化后均保留；该组图片没有触发旧 OpenCV 候选，也没有人工真假标签，因此不构成实际召回率或误检率结论。现场仍应比较模糊、反光真条码和已知误检场景，并观察新增双路推理对帧率的影响。
