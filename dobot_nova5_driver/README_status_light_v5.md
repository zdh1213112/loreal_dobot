# V5 工作站状态灯（默认关闭）

仅 `cosmetic_box_single_arm_cycle_v5_d435.launch.py` 接入。默认：

```bash
ros2 launch dobot_nova5_driver cosmetic_box_single_arm_cycle_v5_d435.launch.py
```

等价于 `alarm_light_enabled:=false`：不启动灯控进程、不打开串口、不新增
状态发布定时器，也不创建灯控状态订阅或静音服务客户端。
V3/V4 启动方式不变。D405、D435 主循环不包含状态灯上报代码。

启用五色科隆威 USB/485 状态灯：

```bash
ros2 launch dobot_nova5_driver cosmetic_box_single_arm_cycle_v5_d435.launch.py \
  alarm_light_enabled:=true \
  alarm_light_port:=/dev/ttyUSB0
```

可选参数：

| launch 参数 | 默认 | 用途 |
| --- | --- | --- |
| `alarm_light_enabled` | `false` | 启用独立灯控进程和界面状态显示 |
| `alarm_light_port` | `/dev/ttyUSB0` | 建议现场改为稳定的 `/dev/serial/by-id/...` 路径 |
| `alarm_light_device_id` | `1` | 合法范围 1～247，不使用广播地址 |
| `alarm_light_buzzer_enabled` | `true` | 设置 `false` 可只亮灯、不鸣叫 |
| `alarm_light_warning_beep_enabled` | `true` | 黄色异常首次出现短鸣约 0.5 秒；设为 `false` 不影响红色故障蜂鸣 |
| `alarm_light_no_target_warning_count` | `3` | 连续几轮无有效抓取目标后黄闪；至少为 1 |

先前版本的 `alarm_light_startup_grace_s` / `alarm_light_status_timeout_s`
已移除。新版不以三秒无消息、模型加载/计算时间或短暂反馈年龄判断故障。

默认串口为 9600、8E1，命令间隔至少 50 ms。协议复用自
`/home/zdh/loreal/alarm_light_controller/src/alarm_light_controller/app.py` 的
CRC 和 0x05 常用控制地址，不启动该 PySide6 界面；其 0x01 独立控制地址
编号不同，没有混用。原 GUI 可用于人工调试，但请先停用自动灯控，
两个程序不能同时占用同一串口。Linux 串口以 exclusive 模式打开。

灯控进程使用现有 `vision_python` 解释器，其中已有 pyserial 3.5。
该进程只导入 ROS、标准库和 pyserial，不加载相机、Qt、YOLO、SAM 或 FFS。

## 灯光含义

| 场景 | 灯光/声音 |
| --- | --- |
| 正在初始化、已请求启动但尚未确认流程继续 | 黄灯 1 Hz 闪烁，无声 |
| 流程明确提示等待 102 VLA 联锁心跳 | 黄灯 1 Hz 闪烁，无声；界面提示启动或检查 102 VLA |
| 单轮流程完成，等待操作 | 白灯常亮，无声 |
| 自动运行、长时间识别、等待上料、正常双臂交接、扫码和翻底 | 绿灯常亮，无声 |
| 单次未找到目标、普通重采集、单帧障碍物待确认、正常交接预跟踪 | 绿灯常亮，无声 |
| 明确抓取失败，返回初始位重新识别/重抓 | 黄灯 1 Hz 闪烁，首次短鸣一次 |
| 翻底重抓丢失视觉目标，返回初始位重新扫码 | 黄灯 1 Hz 闪烁，首次短鸣一次 |
| 连续三轮无有效抓取目标，或上料后多次确认空盘、重新开放上料 | 黄灯 1 Hz 闪烁，首次短鸣一次 |
| 左臂正在请求抓取目标，目标周围/夹指通道点云明确 BLOCKED、禁止抓取 | 黄灯 1 Hz 闪烁，首次短鸣一次；CLEAR 后解除该障碍物提示 |
| 操作员暂停或退出的节点重新连接后等待恢复 | 黄灯常亮，无声 |
| 流程明确发布 FAULT、safety_pause，扫码相机明确发布 FAULT，或已见过的节点发布端消失并持续五秒 | 红灯 2 Hz 闪烁 |
| 故障已确认静音但仍未恢复 | 红灯常亮 |

故障优先于重试/等待/运行，普通识别成功不会清除另一来源的故障。
首次故障鸣叫 3 秒，此后每 30 秒提醒 3 秒；静音后停止蜂鸣。
相同故障码不随反馈年龄变化反复重新触发；故障消除后出现新故障会重新提醒。
故障真实恢复后按当前事件退灯；流程 fatal 故障保留到实际重新开始一轮流程。
正常补料/交接不会蜂鸣，自动翻底本身也不是异常。
黄色异常的短鸣约 0.5 秒，同一段受阻/恢复过程不循环提醒，原因切换也不重复鸣叫。
完全恢复绿灯后再次出现异常，才重新短鸣；静音按钮也能提前结束短鸣。
初始化、启动前等待心跳、主动暂停仍无声。全局 `alarm_light_buzzer_enabled:=false`
关闭所有蜂鸣；只关闭黄色短鸣可使用 `alarm_light_warning_beep_enabled:=false`。

`cycle_start` / “continuous cycle started” 只代表启动请求，不直接亮绿灯。
初始化/等待心跳期间，扫码相机单独就绪、后台扫码阶段完成、普通状态消息
不会覆盖黄闪；对应的联锁 CLEAR、启动运动开始/已到位，或对应联锁阶段
明确成功后才转绿。循环运行后的普通新一轮开始不反复切黄。
灯控启动时即发送设备原生黄闪命令 `0x0007`，不新增 Python 闪烁定时器。

恢复类黄闪不会被普通新一轮开始、返回初始位或后台扫码消息清除；收到本轮
有效目标进入抓取准备/抓取保护阶段，才解除恢复提示。连续无目标按不同轮次计数，
重复消息不累计。真实 102 新上料会清除旧目标相关提示；翻底恢复生成的逻辑上料
事件不等于换了新盒，不会提前清除提示。

障碍物提示只观察已有 `/d405_handoff_zone_state` 的小型 JSON 结果，不订阅实际点云。
左臂请求目标前的旧消息、待机预跟踪、已持盒后的点云、`VERIFYING_BLOCKED`
单帧待确认状态不触发。已确认 `BLOCKED` 的提示保持到新鲜明确的 `CLEAR`，
`VERIFYING_CLEAR` / `REACQUIRE_TARGET` 不提前清除；清除障碍物提示不代表灯控授权抓取，
也不会清掉同时存在的重抓恢复或红色故障。

V5 界面的“状态灯”行显示当前原因和串口通信异常。
“确认报警 / 静音”只改变灯控蜂鸣状态，不清除机械臂故障或启动流程。
也可执行：

```bash
ros2 service call /station_v5/alarm_acknowledge std_srvs/srv/SetBool '{data: true}'
ros2 topic echo /station_v5/alarm_status
```

## 负载与故障隔离

### 102 VLA 提醒接入

101 launch 的 `alarm_light_enabled:=true` 启动整站灯控；102 不由此 launch 启动，
需在原 `examples.dobot_nova5_dh_v5.main` 命令后同时增加：

```text
--args.turntable-interlock --args.alarm-light-enabled
```

102 侧该开关也默认关闭。启用后只对 V5 做适配，不修改通用 RTC/相机库：

| 102 提醒 | 条件 |
| --- | --- |
| 疑似重复动作无进展 | 连续 3 轮相似接近/退回或下降/抬升且无有效交接进度；前 1–2 轮不触发该规则，不要求合爪，不受原 15 秒/35 mm 条件限制，允许速度和起点小幅变化。原 15 秒精确重复/小范围停滞提醒保留；两路均需跨至少三次新推理、十次交付动作，排除正常许可等待、保护避让、预热、主动停机 |
| 推理动作等待恢复 | 连续三次推理失败，或 RTC 已预热后实际队列断供等待超过 0.5 秒；队列低、普通推理延迟不触发 |
| 视觉输入过期 | 核验真实 RealSense 帧号、采集时间和本次观测对应帧龄，超过 1.5 秒；静态画面不等于旧帧 |

这些情况黄闪、首次短鸣一次，不自动停机、开爪或回零，也不表示已确诊空抓/掉料。
已有反馈故障保护和原运行报错停止仍按红灯处理。102 参数可分别通过
`--args.alarm-light-repeat-window-s`、`--args.alarm-light-repeat-position-span-m`（默认 `0.035` 米）、
`--args.alarm-light-repeat-attempts`（默认 `3`，整数且至少为 3）、
`--args.alarm-light-inference-failures`、
`--args.alarm-light-starvation-s`、`--args.alarm-light-frame-max-age-s` 调整。
15 秒重复动作窗口和 35 mm 每轴跨度应结合现场正常动作标定。新增三轮计数
以相对 XYZ 往返轨迹匹配为依据：单轮约 0.8–20 秒，去程至少 20 mm，回程
至少去程的 60% 且不少于 20 mm；反向迟滞 15 mm，相邻轮起点允许最多 80 mm 漂移。
速度变化及单次小幅抬升不清零；有效交接、新计划、正常许可/保护等待、主动停机、
采样或动作断开超过约一秒、明显离开尝试区域会重新累计。各轴独立计数，
不会把同一次往返的 X/Y/Z 分别累计成三轮。
102 启动日志显示启用状态与阈值；状态变化或约十秒输出一次 `102 VLA monitor`
诊断，列出窗口时长、新推理块数、交付动作数和实测 XYZ 跨度；新增
`attempt_rounds`/`attempts_required`（已匹配/要求轮数）、`attempt_axis`、
`attempt_elapsed_s`、`attempt_match_error_mm`，触发时 gate 为 `repeated_attempts`。
`/station_v5/vla102_state` 的 `repeat` 字段包含同一份数值依据，不增加逐帧监测日志。

102 使用现有 ROS 联锁执行器发布 `/station_v5/vla102_state`，无新采样线程，
无图片复制或落盘。灯控按来源独立保存状态：101 成功不能清除 102 警示，
102 正常也不能清除 101 故障；旧会话、旧序号、过期缓存消息不覆盖新状态。
未启用 102 监测时保留原 101 灯控行为，不推断 102 已经健康；消息静默本身不新增故障。

重新规划或 broker reset 会更新监测代次、清理上一阶段的黄色提示；已发出的推理
仍按其开始时的代次处理，迟到结果不能改变新阶段的提示。已有红色流程故障继续保留。
解耦模式下，外层缓冲仍交付动作时不提示内层队列断供。监测/发布回调异常不阻断
原来的动作、停止和断开连接；退出后排队中的旧发布回调不能覆盖最终故障状态。

### 通信与线程隔离

- 灯控只订阅已有的 `/cosmetic_pick_cycle_status`、
  `/cosmetic_pick_cycle_timing`、`/turntable_barcode_camera_status` 和
  `/turntable_barcode_camera_ready`，以及现有的障碍物判定 JSON。
  可选 102 监测只增加上述小型状态 JSON 的订阅。
  障碍物订阅使用 best-effort、depth=1，不增加相机的可靠传输背压。
  主流程没有新增状态发布定时器、
  阶段钩子、反馈采样、机械臂连接、相机订阅或相机上报。
- 正常消息间隔没有报警超时。30 秒甚至更长的推理、扫码、上料等待也不会
  自动变成红灯；单次阶段 error 后正常重试也不等于流程故障。
  102 反馈过期/心跳问题由原有联锁判断：启动前明确等待心跳显示黄闪，
  联锁实际暂停或流程故障显示红灯，
  不再额外按缓存中的 50 ms/500 ms 数值触发一次独立报警。
- 灯控进程以 1 Hz 查询本地 ROS 图缓存。某个已出现的发布端消失且持续五秒，
  才提示节点退出/断开；这不依赖相机是否及时处理完一帧。未收到启动/就绪
  事件时保持初始化提示，不对模型正常加载时间鸣叫。
- 绿灯表示最后收到的流程事件正常，不表示独立验证了每个相机/模型的实时健康。
  挂死但 ROS 发布端仍存在时，本版不会靠消息静默推断红灯；机械臂仍使用原有
  新鲜度和双臂安全联锁。该限制是为了避免把正常重计算当成故障。
- 独立灯控进程持有串口，单个后台线程发送，待发送状态只保留最新一份。
  设备本身负责闪烁；状态不变不重复发送灯控命令。
- 普通状态每秒汇总一次，明确的等待/恢复/故障状态变化立即处理。界面状态最多约每两秒刷新，
  仅在语义状态/故障原因/串口错误变化时打印一次；发送完成、蜂鸣周期切换
  不再反复打印相同报警。
- 黄色异常短鸣由独立灯控进程临时创建一次 ROS 定时回调关闭，结束即销毁；
  短鸣使用原协议的蜂鸣器直接开命令 `0x0004`，避免 1 Hz 周期蜂鸣的起始静音相位，
  红色故障仍使用原有周期蜂鸣。
  不创建额外相机/机械臂线程，不通过提高主流程轮询频率实现短鸣。
- 写超时 200 ms；失败后在灯控进程内每 2 秒重连，恢复后只发送最新状态。
  程序不无限等待回包或执行串口 flush，串口异常不会阻塞机械臂线程。
- `command_applied` 表示本地串口完整写出，不是设备回读确认。现有 GUI
  只显示原始回包，没有确认这台实物的状态查询/ACK 行为，本版不虚报实际灯亮。
- 灯控进程正常退出时全关；已有红色故障时保留红常亮并关闭蜂鸣器。
  整机断电、强杀或 USB 断连后，软件无法保证改变灯光；现有协议未确认
  硬件通信看门狗。状态灯用于提示，不替代双臂现有安全联锁。

实物首次验证应先用原灯控 GUI 确认五色及闪烁命令，再启用 V5。
单元测试使用假串口，不会自动打开实物或驱动机械臂。
