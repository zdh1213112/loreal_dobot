# 右臂放料—左臂控制器转盘 IO—扫码停转—左臂抓取联动方案

本文保留早期联动设计和风险分析。当前脉冲式转盘、D435三秒扫码及V3抓取高度保护的实际实现说明见 `README_cosmetic_box_turntable_v3.md`；本文件中关于HID扫码器和电平运行模式的内容不代表V3现状。接线和转盘驱动器控制方式仍必须先现场确认。

## 已知条件与现有项目边界

- 102 右臂将物料放到转盘；101 左臂负责转盘扫码结束后的抓取。
- 转盘驱动器的控制输入接在 **101 左臂控制器的 DO** 上。101 侧通过 `DobotApiDashboard.DOInstant(index, status)` 可以立即设置 DO；`GetDO(index)` 只能读回输出状态，不等于证明转盘真的旋转或停稳。
- V3左臂循环节点控制101，对102仅使用30004 feedback做位姿联锁和被动TCP Y/Z触发；不打开102的29999 Dashboard，不给102下运动指令。现场边界已配置为102 User 0 / Tool 1中的Y=400mm、Z=200mm。
- HID 扫码节点发布实际码值到 `/detected_barcodes`；左臂循环节点已有订阅和条码回调，默认 `barcode_stable_hits=1`。现有扫码窗口用于左臂**抓取后**的中转位扫码，不能直接当成转盘扫码窗口复用。
- 转盘无法安装有料传感器。因此软件只能根据右臂释放动作完成、右臂离开旋转包络和后续扫码/视觉结果推断放料成功，不能单独证明物料一定留在盘上。

## 推荐联动顺序

1. **待料**：101 控制器 DO 保持转盘停止状态；左臂在转盘外等待。右臂带物料进入放料位。
2. **右臂放料**：VLA正常控制右臂完成放料和抬升，101不接管102。101只在本轮等待物料期间先观察到102 TCP进入放料侧Y≥400mm，随后Y<400mm且Z≥200mm连续同时成立200ms，才在内部生成一次 `place_done`。
3. **启动门槛**：自动 `place_done` 产生后，101继续用已有102 feedback确认反馈新鲜和两臂Y向间距，再允许置运行DO。`/turntable_place_done`保留为手动联调备用。TCP Y/Z只能证明规定的放料—退出轨迹已经发生；没有有料传感器时不能单独证明物料已经释放并留在盘上。
4. **转盘旋转与扫码**：先清空本轮转盘扫码结果，准备只属于本轮的扫码窗口，再通过 101 Dashboard 设置转盘运行 DO；确认命令无错误后才进入 `SCANNING` 并记录 `cycle_id` 和启动时间。启动前或命令尚未确认时的扫码消息不能触发本轮停转。右臂可以继续撤退，但在转盘运动期间不得再进入转盘区域。
5. **读码停转**：只在 `SCANNING` 状态接受启动后收到的、满足码值格式规则的条码。第一条有效码被锁定后，立即关闭本轮扫码窗口并给转盘驱动器发停转指令；重复码不得重复停机或触发下一轮。
6. **停稳确认**：发出停转指令后进入 `STOPPING`，左臂仍禁止进入。首选转盘驱动器的“停止/零速/到位”反馈接到 101 DI，并以有效、稳定的反馈作为门槛。若驱动器没有此反馈，只能使用实测最大停机时间加余量、再由视觉确认物料静止；此退化方案不能证明电机绝对零速，必须经现场风险评估。
7. **左臂抓取**：停稳后，101 才请求 D405/YOLO/SAM2/FFS 重新识别当前转盘上的物料位置，沿用现有的目标稳定和下探通道检查。扫码时的转盘角度不能直接作为固定抓取位；若停止角度使物料落在相机/左臂工作区外，需要驱动器定位到抓取位，或调整扫码器/转盘布置。
8. **完成与复位**：左臂抓起并退出转盘区域后，记录本轮码值和结果，清空联动状态；在转盘停止、上一轮结束的条件下，才接受下一轮 `place_done`。

## 状态与异常出口

| 状态 | 进入条件 | 允许的下一步 | 异常处理 |
| --- | --- | --- | --- |
| `WAIT_PLACE` | 上轮结束、转盘停止 | 收到本轮 `place_done` | 无放料通知则保持停止 |
| `VERIFY_CLEAR` | 右臂释放已确认 | 右臂离开旋转包络后打开扫码窗口并启动 | 右臂反馈过期、未退出或通知重复：不启动 |
| `SCANNING` | 运行 DO 无错误且扫码窗口已激活 | 本轮有效码到达即停转 | 扫码超时、扫码器离线、右臂重新进入或反馈失效、操作员停止：停转并报故障，不让左臂盲抓 |
| `STOPPING` | 停转指令已下发 | 停稳反馈有效后允许视觉检测 | 停稳超时：锁定故障，左臂禁止进入 |
| `READY_PICK` | 转盘停稳且视觉目标有效 | 左臂抓取 | 视觉无目标/目标漂移/通道阻塞：不下降，转人工或受控重试 |
| `FAULT` | 任一门槛失败 | 排查并人工确认复位 | 保持停转请求和左臂禁入；不自动重启上一轮 |

扫描一圈或扫描时间上限只能在测得转速、码面可见范围后设定；它是**故障超时**，不是“无料”传感器。无有料传感器时，放料失手、物料偏移或条码朝向不可见都会表现为未扫码，必须停转检查，不能默认为空盘并继续循环。

## 软件接口与分工

| 来源/去向 | 建议数据或接口 | 责任 |
| --- | --- | --- |
| 102 feedback → 101 联动模块 | 现有30004 TCP位姿、User/Tool及反馈年龄；先Y≥400mm，随后Y<400mm且Z≥200mm保持200ms产生一次事件 | 被动判断右臂放料后退出；现有两臂Y向联锁仍保留，101不向102发运动命令 |
| 手动联调 → 101 联动模块 | `/turntable_place_done` 单次 `Bool(true)` | 仅作备用和调试；自动模式无需VLA发布该话题 |
| 101 联动模块 → 转盘驱动器 | `DOInstant(run_do, 1/0)` **仅适用于电平运行模式** | 唯一软件 IO 写入者；启动、扫码停转、超时和操作员停止都从同一模块发出 |
| 转盘驱动器 → 101 联动模块 | 优选“零速/停止/故障” DI | 确认物理停稳，不用 `GetDO()` 代替 |
| HID 扫码节点 → 联动模块 | `/detected_barcodes` 的码值 | 本轮扫码窗口、码值校验、去重与停转触发 |
| 101 D405 视觉 → 101 抓取流程 | 停稳后的新目标和通道安全结果 | 重新定位后才下发抓取轨迹 |

**IO 极性不能先假定。** 如果驱动器采用启动/停止两个脉冲、使能+方向组合、或需 PLC 中转，DO 数量和指令时序要按驱动器手册重画。101 控制器 DO 只接驱动器控制端，不能直接带电机。`DO()` 是队列指令，不建议用于“扫到立即停转”；联动应优先用 `DOInstant()`，并解析 Dashboard 回复中的错误码。发送成功或 `GetDO()` 返回期望值仍不足以证明电机已停稳。

101 的 Dashboard socket 已由现有 `DobotNova5Controller` 持有。联动模块应复用该连接和统一锁/串行化写入，不再独立建立一个争抢 101 控制权的 Dashboard 客户端。条码回调只记录事件、触发一次停转请求；不要在回调里执行长时间阻塞的停稳等待。节点重启后先核实驱动器/转盘实际状态，不能只把软件状态重置为 `WAIT_PLACE` 就假定转盘已停；若 101 通信中断导致停转命令无法送达，必须由独立硬件停机路径处理。

`/detected_barcodes` 目前是无轮次字段的 `String`。仅按“收到时间晚于启动时间”过滤能降低误触发，但**不能完全排除**上一轮延迟到达的消息。更稳妥的是新增带采集时间/轮次的转盘扫码事件，或在启动前等待扫码枪与上一轮读码完成并清空窗口；消息有效期、`volatile` QoS 只能作为辅助。现有左臂抓取后扫码窗口应与转盘扫码窗口分开，避免转盘条码影响原有 J6 找码和中转位逻辑。

## 现场必须确认的参数

1. 101 控制器接转盘的具体 DO 编号、有效电平、断电/通信失联时的驱动器行为；是否有独立停止输入。
2. 转盘驱动器是否有零速/停止/故障反馈端子；若有，接到哪个 101 DI。若没有，要测量最不利载荷下的最大停机时间并评估视觉静止确认方案。
3. 右臂何时能确认夹爪已释放；其可启动高度/位置、转盘旋转包络和 102 feedback 到该位置的时延。`place_done` 不应在“松爪命令刚发出”时发送。
4. 扫码枪是否能看见转盘上所有可能的码面，旋转多少角度/时间能覆盖；码值格式规则及最长扫码时间。
5. 停转角度是否在 D405 和左臂可抓取范围内；若不在，需要转盘到位控制或重新布置工位。

## 建议验证顺序

先断开电机动力做 IO 和逻辑空载验证：右臂 `place_done` 重复/丢失、旧条码、扫码超时、101/102 feedback 断开时都不得误启动或允许左臂进入。然后低速空盘测启动/停转极性和最坏停机时间，再用固定物料低速验证扫码停转、停稳反馈和 D405 抓取定位。最后才接入双臂自动循环，并验证人工停止、急停和掉电恢复。Python/ROS/TCP 层联锁不是安全认证回路；转盘与机械臂的人员安全应由现场硬件急停/防护回路承担。
