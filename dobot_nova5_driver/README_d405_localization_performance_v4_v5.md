# V4 / V5 D405 定位关键路径优化

目标是缩短 `vision_detection`：停盘后到 D405 输出合格抓取目标的时间。
不调整机器人速度、夹爪动作、模型权重/置信度、固定 ROI、FFS 迭代数、
两帧稳定确认、三维顶面验证、新鲜度或双臂保护。

## 后续第一步：新请求优先及超时诊断

针对定位本身约 0.5 秒、驱动却可能等待 1.5 秒后再次重检的日志，先单独优化：

- 在取帧、YOLO、SAM2、顶部解码、FFS、几何及诊断阶段边界检查是否出现
  新重采集请求。当前一次调用返回后，跳过旧轮次剩余处理，回到循环开头
  由原来的 ACK/采集屏障开始新采集。不终止 GPU 调用，不复用旧结果，
  不提前标记新采集已确认。
- 视觉日志 `[D405 reacquire]` 标出旧处理在哪个阶段让位；
  `[D405 acquisition] request_to_start_ms=...` 表示视觉回调收到新请求后，
  到处理循环开始确认本次重采集的等待时间。自动无目标重试沿用旧请求编号，
  不把它当成一个新的外部请求记录该等待。
- 停盘验收超时保留原提示，并追加 `diagnostics=...`：采集 ACK/时间屏障、
  本轮候选/新鲜跟踪样本数、过期/未来时间戳统计、净空状态、缺少的尺寸，
  以及最后实际评估过的样本对及其位置/角度/尺寸不合格原因。
- `stable_topic_messages_since_wait` 与 `fresh_tracking_samples` 分开统计。
  前者已有两条不代表后者已有两帧。诊断只记录事实，不参与放行或放宽校验。

本轮**尚未实施第二步的两帧交接复用**。仍然使用原来的预抓取话题、两帧门槛、
1.50 秒默认等待上限和失败后的显式重检。不要仅凭相机打印
`Published stable target` 就认为机械臂端已经接受。

## 本次变化

- 顶部条码诊断图的标注、PNG 压缩和写盘移到后台。主线程只复制本次
  图像、掩码、候选及元数据，避免下一帧被磁盘阻塞。队列最多等待 8 份
  任务；磁盘持续阻塞时只跳过新的诊断存图并打印警告，不丢识别帧或结果。
  退出最多等待该后台线程 2 秒。
- 点云预览按每个像素的最近深度批量绘制，保留原来的覆盖顺序与颜色，
  不改变感知使用的点云或采样密度。JPEG 与窗口本身仍在原线程处理，
  本次没有对全部显示链路另起线程。
- D435 已确认侧码时，在停止转盘的阻塞脉冲前关闭顶部检测，并禁止
  在后续 settling 阶段重新打开。没有侧码时，顶部检测照常执行。
- 顶部解码仍保留原来相同顺序的 33 种 ZBar 图像变体，改为按需生成。
  早期解码成功不再提前制作剩余变体；窗口关闭、换轮或重新采集时，
  在推理/各次解码之间及时中止旧任务。返回后再次核对轮次，旧结果不能
  用来累计当前轮次确认。已经进入的单次模型推理不能强行中断。
- 没有把完整条码推理改为异步，以免在缺少真机验证时改变图像/点云匹配。

## 分段计时

每次形成稳定抓取目标时，视觉进程输出一行 `[D405 timing]` JSON：

- `request_to_target_ms`：视觉处理循环确认本次重新采集开始，到发布稳定目标。
- `frames`：这次采集处理过的帧数。
- `stage_ms.capture` / `object_yolo`：首次取帧/清缓存、物料检测。
- `stage_ms.sam_track` / `target_select_sam_init`：跟踪、选目标及 SAM2 初始化。
- `stage_ms.top_barcode`：主线程顶部条码检测/解码。
- `stage_ms.stereo_cloud` / `geometry`：FFS 点云及几何/净空校验。
- `stage_ms.top_verify_debug_enqueue` / `preview`：输出稳定目标前的顶部验证、
  诊断入队与预览工作。目标发布后的显示不计入本次定位耗时。

分段数据是 CPU 墙钟时间，不是 CUDA 独立内核计时；等待下一帧、重置及
其他开销仍包含在总时间内，分段之和不保证等于总时间。

## 验证与启用

离线合成测试（62000 个场景点、3000 个目标点）的完整预览绘制中位数：
修改前约 21.8ms，修改后约 10.2ms，图像像素完全一致。
这是显示环节的 CPU 测试，不代表整轮抓取节省同样比例，也不是现场 GPU 测试。

新增 `test/test_d405_pipeline_performance.py` 检查队列满/写盘失败、快照独立性、
点云覆盖顺序、完整图像一致性、33 个解码变体、取消后旧结果隔离、
V4/V5 侧码确认后的顶部窗口状态，以及计时边界。

构建 `dobot_nova5_driver` 后，重新启动对应的 V4 / V5 launch，驱动与源码视觉
脚本需要一起重启。没有连接相机或下发机械臂动作；实际收益应比较同批物料
的 `vision_detection` 与 `[D405 timing]`，不要仅比较整轮总时间。
