# 化妆品盒转盘扫码 V3

V3使用独立视觉入口
`Fast-FoundationStereoPose-dul_cam/dul_cam/d405_cosmetic_box_leftmost_height75_panel_v3.py`。
V2 launch仍只启动`..._v2.py`，不会加载D435组合画面、D435 ROI事件或V3输出目录。
V3视觉入口使用独立的`handoff_clearance_v3.py`、`gripper_width_policy_v3.py`、
`top_surface_geometry_v3.py`和`top_surface_barcode_detector_v3.py`算法副本，后续修改不会
通过这些模块影响V2。

V3默认开启D405初始位原始图像保存。机械臂位于初始位时，本轮第一次视觉触发保存
两张抓取前RGB；形成稳定目标时再保存两张对应RGB。文件按连续四位序号写入
`Fast-FoundationStereoPose-dul_cam/dul_cam/d405_output_v3/`，不会写入V2目录。

首次完整流程调试默认启用`motion_command_cap_percent:=20`，它在所有普通阶段的速度与
加速度计算完成后统一限制到20%，包括抓取前接近/下降、抓取后抬升、中转、扫码动作、
放置和回初始位。GUI中的“全流程速度/加速度安全上限”可在验证轨迹后逐步提高。两臂
间距联锁触发后的101紧急退让使用独立保护速度，不受该普通动作上限影响。

V3 保留顶面、四周、底面三种物料分支，并独立配置各分支的固定放置高度：

```text
102 右臂VLA的TCP先进入放料侧Y>=400mm
                    -> 随后Y<400mm持续200ms（不判断TCP Z）
                    -> 101 检查 102 TCP 安全间距
                    -> D435持续检测，先保持转盘停止检查当前面1.5秒
                    -> 当前面有条码：不发送DO脉冲，直接进入待抓取
                    -> 当前面无条码：101 DO发启动脉冲，旋转检测最多4秒
                    -> 旋转中检测到条形码后立即发停止脉冲
                    -> 4秒仍无侧码：发停止脉冲，后续由D405检查顶面
                    -> 等待转盘停稳
                    -> 保存“侧码结果已确定、已停稳、待抓取”状态
操作员点击“执行完整一轮” -> D405重新定位并由101左臂抓取
```

分类优先级为：

1. D435 在静止当前面或后续4秒旋转中检测到线性条形码：四周码。抓取后跳过旧 HID
   扫码器和 J6 找码，沿用原四周码放置姿态与放置点。
2. D435 在4秒旋转及停稳阶段均未确认侧码：转盘停止，本件进入左臂待抓状态。
   101正常通过D405定位、抓取并观察顶面；顶面有条码时走顶面分支。
3. D435无侧码且D405也未确认顶码：在D405本轮抓取中心执行底面翻转，
   然后走顶面固定放置分支。

顶面条码分支的固定放置点为 User 0 / Tool 1
`top_surface_barcode_place_xyz=[0.531, 0.328, 0.105]`（mm 表示为
`XYZ=(531,328,105)`）。V3转盘底面翻转完成后也使用这个105 mm放置点。
不启用转盘的旧底面恢复路径仍使用独立的
`bottom_barcode_place_xyz=[0.531, 0.328, 0.215]`。侧面条码分支的放置点
不受顶面高度调整影响。

V3转盘底面翻转在到达本轮初始抓取深度后直接开始，跳过320 mm初次抬升、
中转关节位和User X退让。先夹紧并确认夹持，保持当前XY按`grasp_lift_m`
上升（默认60 mm，只需离开转盘），再把J6吸附到以0°为基准的最近90°
标准面。保持夹持在当前XYZ执行User Rz +40°，随后保持当前XY下降到本轮
首次抓取的绝对User 0 Z并松爪。夹爪打开时在固定XYZ绕当前Tool X轴执行
Rx +70°，重新夹紧后上升160 mm并从吸附后的J6角度+180°。
J6造成的Tool 1反馈TCP XY变化只记录、不阻止流程；随后保持当前XY下降
120 mm并第二次松爪。由于J6已经转动180°，在固定XYZ继续绕当前Tool X轴
执行Rx +70°。动作完成后等待一帧新的D405/SAM跟踪目标，使用该目标最新的
User 0 X/Y下降到本轮首次抓取的绝对Z并重新夹紧；不再使用旋转后的TCP X/Y
盲降。若2秒内没有新鲜跟踪目标，保持开爪并停止流程。Rz +40°状态保持不变。
最后直线上升到转盘安全Z
（默认320 mm），检查夹持反馈，再按顶面分支的固定XYZ放置。每次低位
姿态变化和Z运动均使用Cartesian MovL，并在下发前检查目标逆解；
J6+180°若超过配置的关节限位则停止流程。

相机不可用、转盘停转失败等真实扫描故障仍阻止左臂抓取。

V3沿用V2的图像采集时间与历史TCP对齐、运动趋势不外推机制。偏置高位连续
运动期间若最新D405位置相对首次稳定抓点偏移超过20 mm，但
`near_hover=0`，该帧仅作为眼在手相机运动造成的表观偏移诊断，继续使用首次
稳定抓点，不再返回初始位。只有已经取得悬停区样本、且位置仍无法达到配置的
连续帧共识时，才按目标丢失或SAM掩膜漂移拒绝下降。

`place_done`现在直接表示“102已经放下物料、转盘当前停止”。无须先启动左臂流程：事件到达
后后台线程立即检查两臂间距并开启D435确认窗口。先检查静止当前面，只有当前面没有条码
才发送转盘启动脉冲；侧码确认或搜索超时后确保转盘停止并保存
待抓状态。单轮模式下此时点击“执行完整一轮”，左臂开始正常检测与抓取；
连续模式会自动继续。扫码中或已有待抓物料时，重复的
`Bool(true)`会被忽略，不会累计成多件物料。

D435连续检测默认保持开启，并额外发布“当前画面仍能稳定看到条码”的锁存状态。若
`place_done`到达时当前面已经有稳定条码，本件会直接进入左臂待抓状态，不发送任何转盘
脉冲。若必须旋转搜索，正式检测窗口会一直保持到停止脉冲和静置等待全部完成，因此恰好
在4秒边界或减速停止期间确认的条码仍会被本轮接受。条码离开画面持续1秒后，连续状态
自动清除并为下一件重新布防；左臂取走本件时也会清除本地旧结果，防止上一件误用于下一件。

## 启动前必须配置

转盘采用“每个上升沿切换一次启停”的输入方式。软件脉冲固定为
`0 -> 1 -> 0`，启动和停止各使用一次。`GetDO=0` 只证明机械臂输出已经
复位，不能证明转盘已经停稳。

必须实测并填写：

- `turntable_do_index`：101 控制器实际接线的 DO 编号。
- `turntable_surface_z_m`：转盘上表面在当前 User 0 坐标系下的 Z。当前现场
  实测为 `0.126 m`（126 mm），已写入V3默认参数；负值仍表示未标定并禁止下降。
- `vision_user_z_bias_m`：V3专用D405到User 0的Z向现场标定补偿。四次静止检测
  反推表面为97.1--97.5 mm，而Tool 1实测表面为126.0 mm，因此默认补偿
  `+0.0287 m`。补偿同时用于稳定目标和近抓取复核；V2不使用此参数。
- `grasp_z_offset_m`：V3默认为`-0.004 m`，在75%下探目标基础上再深4 mm；
  转盘表面、Tool 1伸出量和3 mm安全余量组成的绝对Z安全下限仍会硬拒绝过低指令。
- 夹爪闭合逻辑与V2一致：接近时按视觉宽度预张开，到达抓取点后下发
  `position=0.0`全闭指令。夹爪必须在全闭途中碰到物料并连续返回`state=2`
  才允许抬升；到达`0.0 mm`仍为`state=1`则按空抓恢复。
- `turntable_tcp_below_target_m`：夹爪/TCP 定义中，命令抓取点以下仍然
  伸出的实际长度。
- `turntable_settle_s`：第二次脉冲后物料完全静止所需时间，默认 0.5 秒。
- 转盘抓取成功后，D435已确认侧面条码时，从夹稳后的抓取位姿直接开始，
  用一条Cartesian MovL保持TCP的XY不变，在直线上升到`scan_exit_user_xyz`
  的Z（默认320 mm）时同步转动到最近的90度标准面。下发合并MovL前会用
  正逆解检查轨迹；检查不通过则保持旧流程：先直线上升到320 mm，再单独转J6。
  任一运动失败不会自动重试。其他条码面仍使用原来的阻塞式直线上升。
- 标准面对齐以`d435_side_face_reference_joint_deg`（默认0°）为基准，在关节
  安全范围内选择最近的90度锚点；该参数可在V3界面调整，不改变
  `transfer_joint`。到达后检查安全Z、J6角度和夹持反馈，再进入放置路径。
- D435已确认侧面条码的物料跳过D405顶面条码观察及其低位等待；D405目标
  定位与抓取前的安全检查仍照常执行。

示例（数值只能替换成现场实测值）：

```bash
ros2 launch dobot_nova5_driver cosmetic_box_single_arm_cycle_v3.launch.py \
  turntable_do_index:=1 \
  turntable_surface_z_m:=0.126 \
  vision_user_z_bias_m:=0.0287 \
  turntable_tcp_below_target_m:=0.000
```

节点默认从 `UNKNOWN` 状态启动。第一次有效`place_done`按本流程定义同时证明物料已经
放下且转盘停止，因此会把软件状态置为`STOPPED`并立即开始扫码。单独调试转盘、尚未发生
放料事件时，仍可使用“确认转盘当前已停止”；也可传入
`turntable_assume_stopped_on_start:=true`。

## 右臂放料触发

V3默认不接管102，也不向102发送任何运动命令。101通过102的30004只读反馈，
持续检测以下顺序，即使左臂流程尚未启动：

```text
102 User 0 / Tool 1 TCP Y >= 400mm（观察到进入转盘放料侧）
-> TCP退回Y < 400mm
-> Y退出条件连续成立200ms；TCP Z不参与判断
-> 内部产生一次place_done事件并启动后续转盘流程
```

要求先看到Y进入放料侧，可避免节点启动时102本来就在安全位置，或者在其他位置
单纯上下运动时误触发。每轮只接受一次自动事件，上一轮完成并重新进入等待状态后
才会重新布防。相关启动参数为：

```bash
turntable_auto_place_from_secondary_tcp:=true
turntable_secondary_place_y_m:=0.400
turntable_secondary_safe_z_stable_s:=0.200
```

`turntable_secondary_safe_z_m`仅为旧launch命令兼容而保留，当前自动触发逻辑
不会读取它；`turntable_secondary_safe_z_stable_s`虽然保留旧名称，现在只表示
Y退离边界后的稳定时间。

`/turntable_place_done`仍作为手动联调和备用接口：

```bash
ros2 topic pub --once /turntable_place_done std_msgs/msg/Bool "{data: true}"
```

V3不会打开102的29999端口，也不会控制右臂或右臂夹爪。界面的“模拟右臂放料
完成”仅用于单机联调。自动判断只能确认TCP完成规定的放料侧Y进入/Y退出轨迹；
由于现场没有有料传感器，它不能独立证明物料确实已经脱离夹爪。

点击“回初始位并开夹爪”会取消旧的D435转盘扫描、确保转盘停止，并清除上一轮
待抓物料、条码、扫描错误和事件计数。复位后自动触发器先等待102回到
`Y<400mm`一侧，再要求一次全新的`Y>=400mm -> Y<400mm`放料/退离轨迹；
因此旧流程不会在复位后继续，也不会把复位时尚未离开的右臂误当成新一轮。
回初始位成功后会自动建立新的连续等待循环；在收到并完成这次新放料事件之前，
左臂保持初始位不动，无需再次点击“开始连续循环”。

## 抓取高度保护

D405仍然根据顶面、物料高度和75%下探比例发布绝对抓取点。转盘高度不应再
手工叠加一次。V3在下降前反推支撑面：

```text
估计转盘表面Z = 视觉抓取Z - 物料高度 × 25%
```

估计值必须落在 `turntable_surface_z_m ± turntable_surface_tolerance_m`
范围内；命令TCP还必须高于：

```text
转盘表面Z + TCP以下夹爪伸出量 + 表面安全余量
```

任一检查失败时，不下发抓取下降指令。

## D435扫码节点

`d435_turntable_barcode_node_v3.py`绑定相机序列号 `254322071102`，使用现有条码
YOLO权重。该权重实际是普通目标检测模型，只有class 0一个类别；权重元数据虽然把它
命名为`box`，训练数据中的框实际是条码区域。V3只判断“有没有条码”，检测成功后固定
发布`barcode_detected`，不再调用pyzbar放大、旋转和尝试解码。默认使用同权重导出的
`best.onnx`，在当前CPU上保持与`best.pt`相同的检测结果并提高取样帧率。可通过
`turntable_d435_model_path`切回PT权重；ONNX固定使用训练尺寸
`turntable_d435_image_size:=640`。相机提前取流并预热；4秒计时不包含模型加载和相机启动。

D435 ONNX默认使用`turntable_d435_inference_provider:=cuda`。节点会预加载Python环境中的
cuDNN 9，并优先创建`CUDAExecutionProvider`；启动日志中的`provider=`给出实际Provider。
如果CUDA初始化或推理失败，会自动重建CPU会话并记录回退原因。需要强制CPU时传入
`turntable_d435_inference_provider:=cpu`。ONNX Runtime关于`card0/device/vendor`的设备
枚举警告不代表CUDA失败，应以启动日志中的`provider=CUDAExecutionProvider`为准。

默认还启用摄像头扫码器式辅助路径：先调用OpenCV `BarcodeDetector.detect()`寻找平行条纹
四边形，只检测位置、不解码内容。该路径在清晰图上约3ms；同一位置连续3帧成立后才确认，
用来抑制文字和背景纹理的单帧误触发。传统路径没有候选时立即回到现有YOLO，因此不会
牺牲YOLO对模糊、透视和复杂背景的覆盖。预览框上的`SCANNER`表示传统快速路径，
`YOLO 0.xx`表示YOLO路径。可用
`turntable_d435_scanner_assist:=false`关闭辅助，或用
`turntable_d435_scanner_assist_hits:=3`调整连续确认帧数。

D435 YOLO默认置信度为`0.60`，并要求候选框连续2帧且位置有重叠。2026-09-18现场
录屏确认黑色机器人底座会产生`YOLO 0.47`的稳定误检，而真实条码在现有录像中最低约
为`0.72`，因此提高后的阈值会拒绝该背景目标。若更换包装或相机位置后真实条码置信度
明显下降，可通过
`turntable_d435_confidence`调整；不建议直接恢复到`0.20`。

条码可以位于ROI任意位置，包括紧贴上、下、左、右边缘；不再按位置或到边界的距离
硬排除。YOLO候选会额外检查框中央的实际画面：仅当它同时几乎没有明暗变化和局部纹理
时才拒绝。这个保守检查针对录像中的均匀黑色机器人底座，并不要求条码解码成功；若
检测框内可见条纹，即使框贴住ROI边缘，也会继续参与连续帧确认。视频样本复核中，
黑色底座被拒绝，边缘附近真实条码被保留。

D435预览默认开启并嵌入现有D405组合窗口下方，不再创建单独的D435窗口。在下方
D435画面中用鼠标左键拖动即可框选转盘物料ROI，松开后立即生效；右键单击或按
`C` 恢复全画面检测。黄色框是当前有效ROI，蓝色框是正在拖动的区域，绿色框是
本次条码检测结果。也可以通过
`turntable_d435_roi_x/y/width/height` 设置启动时的初始ROI；如现场不需要窗口，传入
`turntable_d435_preview:=false`，此时D405组合窗口下方会显示等待画面。建议把范围缩到
条码经过的转盘物料区域，避免背景中的其他包装条码触发停转，同时让条码在640输入中
占据更多像素。不要为了小目标直接把模型输入改成960；当前权重在运动模糊验证中，960
比训练尺寸640更慢且召回更低。

D435画面右上角提供两个运行时亮暗按钮：`DARKER -`与`BRIGHTER +`。每次点击只把
D435手动曝光减少或增加10，并按相机实际支持范围限幅；画面上的`exposure/gain`会立即
更新。它不会改变D405、ROI、YOLO阈值或转盘控制。也可在鼠标焦点位于D435画面时使用
`[`和`]`执行相同调节。

V3启动时默认开启“D435 连续检测”。开启后，D435会持续在当前ROI内
执行条码检测，画面状态显示为 `CONTINUOUS`，直到再次点击关闭；它不会启动转盘、
不会发送机械臂指令，也不会替代右臂放料完成和两臂安全联锁。收到放料完成事件后，
正式确认窗口先观察已经停止的当前面1.5秒；如果条码本来就朝向D435，就直接把物料标记
为待抓取，不启动转盘。静止检查未确认时才旋转搜索。界面“转盘 / D435”状态栏显示
连续检测开关状态和最近一次检测结果。同一个持续可见的条码只发布一次；条码从ROI消失
至少1秒后才重新布防，因此固定条码不会持续刷日志，移走后放入下一件仍能再次检测。

转盘运动时使用D435 RGB短曝光，默认关闭自动曝光并设置
`turntable_d435_exposure:=50`、`turntable_d435_gain:=128`。自动曝光在室内光线下可能
选择较长快门，造成旋转条码拖影，表现为“转动时检测不到，停止后立即检测到”。D435
画面会显示相机实际采用的曝光、增益和ROI清晰度 `sharpness`。节点会把请求值限制在
相机实际支持范围内。当前默认值优先用较高增益补亮，同时保持短曝光冻结旋转条纹。
若现场仍然偏暗，可小幅增加曝光，例如：
