# 2026-09-02 化妆品盒双臂流程更新记录

## 今日新增功能

1. **102 右臂 TCP 只读安全监控**
   - 101 左臂通过 102 的 `30004` feedback 读取 TCP 位姿。
   - 不打开 102 的 `29999` Dashboard，不发送 102 运动指令。
   - 默认使用 `User 0 / Tool 1`。
   - 102 基座位于 101 的 `-Y` 方向 `725 mm`：
     `Y102_common = Y102 - 725 mm`。
   - 两个 TCP 的公共坐标系 Y 间距小于 `150 mm` 时，101 保持等待；达到或超过 `150 mm` 后自动继续。
   - 反馈断开、过期或坐标系不匹配时，101 闭锁并自动重试。

2. **启动时打印 102 当前 TCP 位姿**
   - 输出 `XYZ`、`RPY`、`User/Tool`、反馈年龄和换算后的 `common_Y_for_101`。

3. **故障可视化快照保存**
   - 每次故障或可恢复抓取失败保存一张可视化面板 PNG 和对应 JSON 分析信息。
   - 保存目录与 `d405_output` 同级：
     `/home/zdh/ffs_ws/src/Fast-FoundationStereoPose-dul_cam/dul_cam/d405_fault_snapshots`

4. **机器人反馈时间对齐**
   - 101 feedback 历史优先使用 Dobot `30004` 数据包中的 `TimeStamp`：Unix 时间直接使用，控制器相对时间按 8 ms feedback 周期映射到主机时间；无法识别时才回退到主机收包时间。
   - D405 使用 RealSense 设备帧时间映射到主机 Unix 时间。视觉帧与机器人位姿因此按采集时刻插值，不再把处理完成时的当前 TCP 位姿套到旧图像上。

5. **预抓取二次确认的安全修正**
   - 保留真实目标移动所需的修正：最新悬停附近实测帧超过 7 mm 且至少两个连续位置一致时，在安全高度水平修正一次；到达悬停位后只消费已经到达的帧，不新增等待。
   - 取消移动相机阶段的目标速度预测和修正完成后的二次外推。运动轨迹仍写入日志，但只用于诊断，不能改变抓取点。
   - 7 mm 内的小变化完整保留首次稳定 XY，不再把小偏差藏在下降直线中，保证下降段为垂直运动。
   - 平放盒子默认锁定首次稳定姿态；即使打开可选姿态跟随，也只有在目标位置已有可靠移动证据、且至少 3 帧旋转共识/平面法向一致时才允许更新。平放目标常见的 OBB 90°轴跳变不会再直接驱动 TCP 斜插。
   - D405 OBB 长轴增加帧间符号连续性处理，减少矩形长轴正负翻转造成的姿态跳变。

6. **高盒/近方形盒抓取方向保护**
   - 不再用包含正面、侧面的整个 SAM 2D 轮廓计算夹爪方向；先用桌面法向选择真实顶面，再仅用顶面 3D 点拟合盒边。
   - 近方形顶面发生 90° 长短边标签互换时保持上一帧边方向，避免两个正交姿态被滤波成约 45° 的对角抓取。
   - 夹爪状态为 `GRIPPED` 还必须满足相对预张开至少闭合 `5 mm`；闭合量不足时禁止抬升，先原地开爪，再垂直退出并重试。
   - 顶面选择方式、顶面点数和抓取轴来源写入故障 JSON 及可视化底部，便于后续复盘。
   - 顶面矩形首帧继续采用旧版轴方向约定，后续帧跟随首帧，避免同一夹持轴选择反向而让腕部额外绕 Z 旋转 180°。

7. **夹爪两侧障碍与目标漂移下降闭锁**
   - 发布目标前，除原有正上方/右侧交接通道外，同时检查目标局部 `-Y/+Y` 两侧的手指垂直下探通道；任意一侧存在至少 20 点的连通障碍簇，本轮目标就不会发布，101 不会开始下降。
   - 两侧检查只覆盖夹爪中央约 60 mm 的手指工作段，从目标侧壁外 4 mm 起向外检查 30 mm，并在 75% 抓取深度处截止，排除目标自身侧壁和桌面。
   - 悬停复检若目标相对初始抓点跳变超过 20 mm、但没有至少两帧位置共识，按目标丢失/SAM 掩膜漂移处理，直接回初始位重新检测。

## 遇到的问题与处理方法

| 问题 | 处理方法 |
|---|---|
| 102 VLA 无法连接 | 原程序同时打开 102 的 `29999` 和 `30004`。改为只打开 `30004` feedback，保留 VLA 对 `29999` 的控制权。 |
| 启动后无法确认 102 是否真的有 TCP 位姿 | feedback-only 连接必须等待首个带 TCP 位姿字段的数据，并在启动日志中打印位姿。 |
| 视觉帧时间与机器人反馈时间不一致 | 使用 D405 设备时间；Dobot `TimeStamp` 支持 Unix 时钟和控制器相对时钟映射，无法识别时明确回退到主机收包时间，并按历史 TCP 位姿插值。 |
| 二次确认后静止目标被误判为移动 | 实机发现移动相机的时间残差也能形成“低残差直线”，因此彻底禁止运动趋势驱动/外推抓点，只接受最新悬停附近的连续实测共识。 |
| 真实移动目标不能修正 | 保留实时 XY 修正；目标移动后只要最新连续两帧稳定在新位置，就会在安全高度横移后垂直下降，不增加固定等待。 |
| 修正后下夹爪戳到目标 | 取消修正动作期间的再次估计和第二次外推；7 mm 内直接使用初始抓点，超过阈值时下降点严格等于已确认的实测共识。 |
| 平放目标 TCP 偶发转歪 | 姿态改用 SO(3) 几何角度和多帧共识；位置没有可靠移动证据时锁定首次姿态，过滤 OBB 90°跳变。 |
| 抓取后夹爪掉盒 | 保留闭合后的双次确认，并在抬升后再次确认；失败时回初始位并重新检测。 |
| 高盒下夹爪时戳到顶面（0165 / cycle 1398） | 该轮目标估计短边约 69 mm、预张开 89.3 mm，但闭合后仍为 89.1 mm，说明手指没有进入两侧。根因是整目标 2D 轮廓受高盒正面/侧面影响，近方形两帧还可能交换 90° 轴并被平滑成对角方向。改为桌面对齐的 3D 顶面边拟合，并增加最小闭合量硬保护。 |
| 假 `GRIPPED` 后抬升命令卡住 60 秒 | 不再只信 DH 状态码；闭合量不足 5 mm 时在抬升前判失败，开爪并垂直撤离，避免再发送受阻抬升命令。 |
| 新顶面拟合后抓取前额外绕 Z 转 180° | 顶面矩形的长轴存在正负二义性，新实现首帧缺少旧版 `camera Y <= 0` 方向约束。已恢复旧约定，并继续用前一帧锁定后续方向；不改变抓点、夹爪宽度或流程耗时。 |
| 0171/0172 误把桌面区域当目标并下爪 | cycle 924 初始高度仅 21.1 mm，悬停后最新跟踪点相对初始抓点跳了 47.0 mm，且只有 1 帧、位置共识为 0，原逻辑仍保留旧抓点继续下降。现在大幅未确认跳变会中止抓取；目标两侧的手指下探通道也纳入两帧 CLEAR 硬门禁。 |
| D405 无目标、ROI 外目标或交接区被点云判定阻塞 | 当前按安全策略重试；交接区阻塞时等待 102 退让或超时后重新请求视觉。 |
